# 变更记录模板

落盘路径：`<落盘根>/changes/<分支短名>/<NNN-业务>/<NNN-批次>/<NNN-简述>.md`

---

## 变更记录骨架

```markdown
# <NNN> <一句话简述>

- 编号：<NNN>
- 日期：<yyyy-MM-dd>
- 分支：<完整分支名>
- 业务 · 批次：`<NNN-业务>` / `<NNN-批次>`
- 摘要：<一句话说清这次干了什么>
- 取代 / 修正：<若本条推翻了同批次此前某条，写「取代 003」；没有就删掉这行>

## 1. 层次对照

<表头按项目配置「变更记录层次映射」展开。后端典型形态：>

| 接口路径 · 字段 | CRUD | Controller 方法 | Service 方法 | 数据库表 · 字段 | 表操作 |
|---|---|---|---|---|---|
| `POST /api/user/import` · `phone` | 增 | `UserController#import` | `UserServiceImpl#importUsers` | `user.phone` | 写 |

<前端项目典型形态：>

| 页面 · 交互 | CRUD | 组件 | 调用接口 | 备注 |
|---|---|---|---|---|

- 接口层用：增 / 删 / 改 / 查；存储层用：读 / 写 / DDL。
- 一行里两者都标，体现「接口这个动作落到存储上是读还是写」。
- 查不到的填「待回填」，别编。

## 2. 影响面 / 兼容性

- 关联的其他接口 / 页面 / 业务：<有就列，没有写「无」>
- 是否破坏兼容：<是/否 + 说明>
- 是否需要数据迁移或 DDL：<是/否>
- **回滚方式**：<含 DDL / 迁移 / 配置变更时必填——怎么安全退回去；纯代码改动写「git revert 即可」>

## 3. 关联产物

- 需求：`<落盘根>/requirement/<同分支>/<同业务>/<同批次>/001-需求文档.md`
- 对接方案：<配置启用 contract 且动了契约时填路径，否则「无」>
- SQL：<配置启用 sql 且有脚本时填路径，否则「无」>

### 本次是否动了接口契约？

<仅配置启用 contract 时回答>

- 动了 / 没动：<明确回答>
- 动了的话：对接方案路径 <path>；契约载体（按配置）里的描述是否已更新 <是/否>

## 4. 复查指引（供日后排查用）

- **关键文件 · 类 · 方法**：
  - `<相对路径>#<方法>` —— <核心改动点在哪>
- **关键查询 / 库表**：
  - <动了或依赖了哪些语句、哪些表的哪些字段；有 DDL/迁移则点明>
- **易错点 · 风险点 · 边界假设**：
  - <本次改动依赖的前提、坑点、共享符号的影响面、容易回归出错的地方>
- **怎么验证这次改动是对的**：
  - 验证入口：<接口 / 页面 / 测试点>
  - 构造数据：<造什么数据>
  - 预期结果：<应该看到什么>

## 5. 为什么这么改

- <关键取舍：为什么选这个方案、排除了哪些替代做法>
- <哪些是**有意为之**的逻辑，不是疏漏——防止日后被当 bug 改回去>

## 6. 已知遗留 / 未覆盖

- <本次有意没做的边界、临时方案、待优化点；没有就写「无」>
```

## 约定库条目格式

写入前先查同主题、写完跑体检，步骤见 `SKILL.md`《先查、再写、写完量一下》；格式与预算见 `using-docflow`《约定库》。

```markdown
- 【2026-08-23】X 框架批量接口超 500 条会静默截断，批量调用一律分页。出处：002-批量截断改分页.md
- 【2026-08-23】新建的常量一律进 `constant/` 下按域已有的类，先找同义常量再新建。出处：001-列配置常量化.md
```

**反例**（不要这样写）：

```markdown
- 关于批量保存的问题：我们在用户导入功能中发现，当使用 X 框架的 batchSave 方法时，
  如果一次传入超过 500 条记录，框架会静默截断……（此处省略 200 字原理分析）
  解决方案是改成分页调用，每页 500 条，具体实现见……
```

详情属于变更记录，不属于约定库。**注意反例的病不在「占了三行」**：把它挤成一行九百字照样是反例——量的是字数。
