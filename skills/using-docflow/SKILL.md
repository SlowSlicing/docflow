# docflow 总规则

docflow 把开发全链路的文档落盘做成固定套路：**需求分析 → 对接方案 → 表设计 → 实现记录**，四类产物按同一套目录规则组织、横向对齐，事后能从「为什么做」一路追到「怎么改的库表」。

本文件是**目录、编号、批次规则的单一事实源**。其他 docflow skill 引用本文而不重复抄写——规则要改只改这里。

## 开工三读（所有 docflow skill 的第一步）

1. **读项目配置** `<落盘根>/000-项目配置.md`（默认落盘根为 `.local/docs/`）。
   **配置文件不存在 → 停下，引导用户跑 `docflow-setup`，绝不自行猜测路径与规则。**
2. **读约定库** `<落盘根>/conventions/` 下各文件（**不含 `归档/` 子目录**）——项目沉淀的做法、口径与踩坑，本次工作要遵守。
3. **读本次要用的模板**（在对应 skill 的 `references/` 下）。

## 四层目录

```
<落盘根>/<产物类型>/<分支短名>/<NNN-业务>/<NNN-批次>/<NNN-文件>
```

| 层 | 规则 |
|---|---|
| 产物类型 | 见下《产物类型》。按月组织的 notes/analysis 不走这四层 |
| 分支短名 | 按配置「分支短名规则」取，默认 = 分支名最后一段（`feature/x/1.2.0-20260301` → `1.2.0-20260301`）。用 `git branch --show-current` 确认 |
| 业务 | `NNN-业务简述`，`NNN` 三位、该分支内按业务出现顺序递增（扫现有最大号 +1） |
| 批次 | `NNN-本批做的事`，该业务内递增，首批固定叫 `001-初版`。开不开新批次见下 |
| 文件 | 一律 `NNN-` 三位前缀，**前缀后必须带能区分内容的描述**（`002-批量截断改分页.md` ✅ / `002-修复.md` ❌）。各类产物的文件规则见各自 skill |

**跨类型同号同名**：同一业务、同一批次在各产物类型下用**完全相同的编号与名字**，横向对得上。

**允许缺席**：某批次不涉及某类产物就没有那个目录（纯重构批次没有 contract，无 DDL 批次没有 sql）。**缺席不占位、不建空目录。**

**号不复用**：删掉的编号不回收，保持时间线可读。

> **为什么文件名一定要带描述**：编号是**批次内**递增的，`011` 在每个批次里都会出现一次；
> 描述那段才是让文件名**全局唯一**的东西，而《引用格式》「只写文件名」的写法正建立在这个唯一性上。
> 写成 `011-修复.md`，引用当场失效——读者只能拿着一个跨批次重名的编号去猜。

## 什么时候开新批次

判据只看一件事：**需求输入变没变。**

| 开新批次 ✅ | 不开，归当前批次 ❌ |
|---|---|
| 产品提了新诉求 | 自测发现的 bug |
| 产品改了原需求 | 把本批没写完的接口写完 |
| 新设计稿下来、页面改版 | 对方反馈字段名想换个叫法 |
| | 代码评审意见、重构 |
| | 上一批原本就没说清、这次补明确 |

不开新批次的改动，只在当前批次目录内新增文件（changes 侧）或原地更新源文件（requirement 侧）。

**拿不准就问用户，别自己定。**

### 上一批还没开工就被推翻

**判据不变，照常开新批次**——「还没写代码」不在判据里，需求输入变了就是变了。

这时上一批会成为**空壳批次**（requirement 侧有文档，changes/sql 侧永远缺席）。这是合法的（缺席不占位），但**必须标注**——否则后人会当成漏做，或者 grep 到那份已作废的口径当真：

- 新批次的需求文档里写明「上一批未开工即被本次变更取代」；
- 上一批的**需求文档与实现计划各在顶部加一行**「**本批未开工，已被 `<NNN>-<新批次>` 取代**」。**只加这一行**：正文、要点清单、任务状态一个字不改。

**两份都要标**：作废的口径住在需求文档里（最容易误导后人），而实现计划那一排「未开始」最像漏做。

这是「上一批产物保持原样不动」的**唯一例外**——加一行取代标记不是改写历史，把新口径写进旧文档才是。

空壳批次本身是有信息的——它记录了「当时定过这个口径、还没动手就变了」。**别为了目录好看去原地改上一批**，那会把这段真实的反复抹掉。

## 产物类型

| 档 | 类型 | 说明 |
|---|---|---|
| **核心**（所有项目都有） | `requirement` | 需求文档 + 实现计划 |
| | `changes` | 实现记录（三层对照） |
| | `notes` | 探讨方案、找解法（按月） |
| | `analysis` | 分析归纳产物（按月） |
| | `conventions` | 约定库（不分层，见下） |
| **可选**（配置启停） | `contract` | 对接方案（给前端/调用方的接口方案）。存量项目可能用别的目录名，见配置「目录名映射」 |
| | `sql` | 表设计与迁移脚本 |
| **自定义**（配置可加） | 任意 | 沿用同一套四层目录与编号规则，但 docflow 不为其提供专门工作流 |

**配置里没启用的类型：不建目录、对应 skill 不触发、相关必答问不问。**

## 按月组织的两类

`notes/` 与 `analysis/` 天然跨分支跨业务，不走四层目录：

```
<落盘根>/notes/<yyyy年MM月>/<NNN-要干什么>.md
<落盘根>/analysis/<yyyy年MM月>/<NNN-主题>/…
```

- 月份用中文两位格式（`2026年08月`），**归开工那个月**，跨月继续写的不搬家。
- `NNN` 在月份目录内从 001 递增，跨月重新从 001 起。
- 同一话题后续补充**直接改那一篇**，不新开；探讨对象真的换了才新开。
- 两者怎么分：**素材已在手、要归纳成「它现在是什么样」→ analysis；问题在手、答案不在、要探索出「怎么回事/我们决定怎么做」→ notes。分不清先落 notes，别两处各写一份。**

## 引用格式

指路的目标是**读者凭它能立刻打开**，不是「路径写得全」。两个方向都算不合格：

- ❌ **光秃秃的编号**——「见变更记录 011」「见 §3.5」。编号是**批次内**递增的，跨批次必然重名；
  自创的简写（如用 `003/006` 表示「批次 003 的第 006 号」）更是只有写的人能解析。
- ❌ **无脑贴完整路径**——`<落盘根>/changes/<分支短名>/<NNN-业务>/<NNN-批次>/<NNN-文件>.md`
  动辄七八十字符，写进代码注释要折两行，正文被路径淹没。

**正解：最短的唯一标识 + 锚点标题原文。**

| 情况 | 写法 | 例 |
|---|---|---|
| **文件名全局唯一**——带描述的 `NNN-xxx.md`（变更记录、notes、analysis 产物等） | **只写文件名** | `详见 002-批量截断改分页.md` |
| **文件名不唯一**——各批次同名的固定文件（`001-需求文档.md` / `001-实现计划.md` / 各 skill 约定的固定名产物） | 补**批次目录名** | `见《003-对账优化》需求文档 §4.2「重试与幂等」` |
| 批次名是 `001-初版` 这种**跨业务重名**的 | 再补**业务名** | `见《003-对账优化/001-初版》实现计划 §2` |

**锚点必须带标题原文**，别只给 `§4.2`：标题原文本身就是唯一可 grep 串，路径写错也能靠它找回来；
只给章节号，读者还得打开文件数章节。

**自检**：拿这串去编辑器的「按文件名跳转」、或 `find <落盘根> -name "002-批量截断*"`，能不能一次命中？
能就够了，多余的路径不要写；不能就补到能为止。

**适用范围**：约定库的出处链接、变更记录的关联产物、文档之间的互引、
以及**代码注释里指向落盘产物**时，一律照此写。同一份文件内部引用自己的章节（`§4.2`）不受此限。

## 约定库

路径 `<落盘根>/conventions/`，按域分文件：`001-流程约定.md`、`002-编码约定.md`、`003-踩坑记录.md`（项目可加域）。
退休的条目移到 `conventions/归档/<同名文件>`，**开工不读、不计预算**，要查时 grep。

**条目格式（硬约束）**：日期 + 一句话规则 + 出处链接（格式见上《引用格式》），**整条（含日期与出处）不超过单条上限**。

```markdown
- 【2026-08-23】X 框架批量接口超 500 条会静默截断，批量调用一律分页。出处：002-分页调用.md
```

**详情永远不搬进约定库**——要细节顺着出处链接回原文看。

### 预算：约定库是每次开工都要读完的东西，所以有上限

| 项 | 默认 | 为什么按这个量 |
|---|---|---|
| 单条上限 | 150 字（按字符，不按行数） | 「最多两行」挡不住一行九百字的条目 |
| 单文件条数 | 50 条 | 一屏扫不完就等于没读 |
| 单文件字数 | 8000 字（条目之外的正文也算） | 挡住「不按条目写、整段写成小论文」 |

项目要改默认值，在配置「项目备注」里写一行 `约定库预算：单条 N 字，单文件 N 条 / N 字`。
体检命令（只读，有警告 exit 1），项目改过预算时带上对应参数：

```bash
python3 <docflow包>/scripts/build-index.py <落盘根> --check-only \
  [--conv-max-chars N] [--conv-max-entries N] [--conv-max-file-chars N]
```

**超预算不是警告了事**：谁写入之后发现超了，谁就地按 `docflow-retro`《自动整理》把那个文件收回预算内，
整理完再报告。约定库只有「写入」一条路而没有「收敛」时，三周就能涨到二十几万字、六百多条，
其中已有过时与自相矛盾的条目——读的人分不出哪条还算数。

## 索引

`<落盘根>/INDEX.md` 由脚本生成，**是缓存不是账本**——不手工维护，随时重建：

```bash
python3 <docflow包>/scripts/build-index.py <落盘根>
```

`<docflow包>` = 本 skill 目录的上两级（`.../docflow/skills/using-docflow/` → `.../docflow/`）。skill 目录通常是软链，用 `ls -l ~/.claude/skills/using-docflow` 看链接指向即可。

### 没有 python3 的机器怎么办

**索引是优化，不是必需——落盘的文档本身才是事实来源。** 先探一下：

```bash
command -v python3 || command -v /usr/bin/python3 || echo "无 python3"
```

（脚本只用标准库，Python 3.6+ 都能跑；macOS 装了 Xcode Command Line Tools 就自带 `/usr/bin/python3`。）

**真的没有就直接扫目录，别卡在这一步**：

```bash
ls <落盘根>/requirement/*/                              # 有哪些分支、哪些业务
grep -rl "<业务关键词>" <落盘根>/requirement/            # 按关键词找业务
grep -rn "^- 承接自：" <落盘根>/requirement/ | grep -v "：无"   # 承接链全景
grep -rn "^- 一句话目标：" <落盘根>/requirement/          # 各业务在做什么
```

**降级后损失的**（改成人工留意，别当它不存在）：跨产物类型的聚合视图、业务撞号与承接悬空的自动体检、按最近改动排序。定新编号前记得自己 `ls` 一眼确认号没被占。

每业务一行：分支短名、业务、批次数、最新批次、一句话目标、承接自、有哪些产物、最近改动。附带两项体检：承接链悬空、业务撞号（加 `--check-only` 只体检不写文件）。

**要追一个业务的历史（尤其跨分支多次改过的）→ 先重建索引再读，别手工翻目录。**

## 路由：该用哪个 skill

| 情况 | 用 |
|---|---|
| 项目没接入 / 缺 `000-项目配置.md` | `docflow-setup` |
| 拿到全新需求要分析落盘 | `docflow-requirement` |
| 要改已落盘的需求产物（产品改了口径 / 提了新诉求） | `docflow-evolve`。**只是在已有功能上写代码、不用动需求文档 → 走下面两条，别走 evolve** |
| 按实现计划写代码、维护任务状态 | `docflow-implement` |
| 代码改完了要记录 | `docflow-changes` |
| 接口契约变了、要给调用方出对接方案 | `docflow-contract`（需配置启用） |
| 想知道某业务历史上怎么演进的（只查不改） | `docflow-trace` |
| 方案探讨、技术选型、排查调研要落笔记 | `docflow-notes` |
| 复盘提炼、整理约定库 | `docflow-retro` |
| 素材已在手，要系统分析归纳成规范文档 | `docflow-analysis` |
| 只是想知道规则（放哪、怎么编号、开不开批次） | 本文件即可 |

## 落盘前自检

- [ ] 读过项目配置与约定库了？
- [ ] 分支短名是 `git branch --show-current` 确认过的？
- [ ] 业务号是扫过现有目录取的最大号 +1，不是拍脑袋？
- [ ] 该开新批次的开了、不该开的没开（判据 = 需求输入变没变）？
- [ ] 文件名带 `NNN-` 前缀，没往上层目录扁平堆？
- [ ] 跨类型的同一业务，编号与名字完全一致？
- [ ] 没建空目录占位？
