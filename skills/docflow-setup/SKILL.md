# 项目接入 docflow

生成这个项目的 `000-项目配置.md`（所有 docflow skill 的开工必读项），并建好落盘骨架。

**REQUIRED BACKGROUND:** 目录与编号规则见 `using-docflow`，本文不重复。

## 两种模式

先看 `<落盘根候选>` 有没有存量文档：

- **全新接入**：没有存量 → 生成配置 + 建骨架。
- **迁移模式**：已有存量（不管是不是按 docflow 组织的）→ **只生成配置，存量一个字都不动**。

## 第一步：检测（先查再问）

| 查什么 | 怎么查 | 用于 |
|---|---|---|
| 是不是 git 仓库、当前分支 | `git rev-parse --is-inside-work-tree`、`git branch --show-current` | 分支短名规则、隔离方式 |
| 技术栈 | 构建文件（`pom.xml`/`package.json`/`go.mod`/`Cargo.toml`…）、目录形态 | 推荐启用哪些产物类型、变更记录层次映射 |
| 有无存量落盘目录 | 找 `.local/docs`、`docs/`、`.docs/` 等 | 判断走哪种模式 |
| 存量目录名 | `ls <落盘根>` | 是否需要「目录名映射」（如存量把对接方案叫 `frontend`） |
| 落盘根是否已是独立 git | `git -C <落盘根>/.. rev-parse` | 是否需要 git init |

检测能定的就填默认值让用户确认，**定不了的才问**。

## 第二步：逐字段确认配置

11 个字段，一个都不能少（顺序即下表）：

| 字段 | 默认值 / 怎么定 |
|---|---|
| 落盘根目录 | `.local/docs/` |
| 分支短名规则 | 取分支名最后一段 |
| 启用产物类型 | 核心类型必开；`contract`/`sql` 按项目形态推荐——**判断依据与三种典型形态的完整配置见 `references/config-examples.md`**（后端服务 / 前端应用 / 内部库 CLI），含事后改主意怎么办 |
| 目录名映射 | 默认无。存量项目若已用别的目录名（如 `frontend` 对应 contract），在此登记 |
| 变更记录层次映射 | 按技术栈定。后端典型：`接口 ↔ Controller ↔ Service ↔ 表`；前端典型：`页面 ↔ 组件 ↔ 接口`；库项目：`公开 API ↔ 内部模块` |
| 现状调查数据源 | 有数据库 MCP / 只读连接就登记（含库名、只读性、默认租户等约束）；没有填「无，现状以代码为准」 |
| 接口契约载体 | 契约文档在哪（Apifox / Swagger UI / 仓库内某目录 / 无） |
| 对端仓库 | 前后端分离时对方仓库路径 + **只读**约束；无则填无 |
| git 隔离方式 | 默认：主仓库 `.git/info/exclude` 加一行 `.local`（**不带尾斜杠**） |
| 语言 | 默认中文 |
| 接入包版本 | 自动取：`git -C <docflow包> describe --always` |

**判不出来的字段填「待确认」并在配置末尾列出，不要编造。**

## 第三步：落地

```bash
# 1. 落盘根 + 约定库（只建这两个，其余类型目录用到再建——缺席原则）
mkdir -p <落盘根>/conventions

# 2. 落盘根所在目录设为独立 git 仓库（若尚不是）
git -C <落盘根>/.. init

# 3. 主仓库隔离（注意不带尾斜杠：worktree 里它可能是软链，带斜杠匹配不到）
echo '.local' >> .git/info/exclude
```

然后写 `<落盘根>/000-项目配置.md`：

```markdown
# docflow 项目配置

> 所有 docflow skill 开工必读。字段含义见 docflow-setup。

| 配置项 | 取值 |
|---|---|
| 落盘根目录 | `.local/docs/` |
| 分支短名规则 | 取分支名最后一段 |
| 启用产物类型 | requirement, changes, notes, analysis, conventions, contract, sql |
| 目录名映射 | 无 |
| 变更记录层次映射 | 接口 ↔ Controller ↔ Service ↔ 表 |
| 现状调查数据源 | 无，现状以代码为准 |
| 接口契约载体 | 无 |
| 对端仓库 | 无 |
| git 隔离方式 | 主仓库 .git/info/exclude 加 `.local` |
| 语言 | 中文 |
| 接入包版本 | <git describe 结果> |

## 待确认

- <判不出来的字段列在这里；没有就写「无」>

## 项目备注

- <该项目特有的、不属于上述字段但 agent 该知道的约定；没有就写「无」>
```

## 迁移模式的硬约束

- **存量文件零改动**：不重排、不改名、不补元信息、不建缺失的目录。落完配置用 `git -C <落盘根>/.. status` 验证只多了配置文件。
- **体检只转告不代修**：跑 `python3 <docflow包>/scripts/build-index.py <落盘根> --check-only`，把撞号、承接悬空等问题**报告给用户**，修不修由用户定。
- 存量的新旧形态并存是正常的（老业务可能没有批次层）。**新规则只对以后的新产物生效**，这一点写进配置的「项目备注」。

## 收尾

1. 告知配置文件路径，请用户核对（尤其「待确认」那几项）。
2. 提醒备份：落盘根是纯本地 git，**机器坏了全丢**。建议配一个**私有** remote 定期 push——落盘内容含业务信息，**严禁推公网**。
3. 配置确认后可在落盘仓库内提交：`git -C <落盘根>/.. add -A && git -C <落盘根>/.. commit -m "接入 docflow"`。

## 升级检查模式

用户说「docflow 升级了，检查一下配置」时：对比包的 `CHANGELOG.md` 与配置里的「接入包版本」，列出这期间影响存量的规则变化（模板字段、目录规则、配置字段增减），给出迁移建议，**改不改由用户定**，改完更新「接入包版本」。
