# 项目配置样例（按项目形态）

`contract` 与 `sql` 是可选类型，**接入时由 setup 检测并推荐、用户确认后写死在配置里**。下面三种典型形态可直接抄改。

## 可选类型开不开：判断依据

| 类型 | 开 | 关 |
|---|---|---|
| **contract**（对接方案） | 有**别人**要照着你的接口写代码：前后端分离、对外 API、SDK、被其他服务调用 | 只有自己用：CLI、脚本、内部库、纯本地工具；或前端项目里接口是别人定的（你是消费方不是提供方） |
| **sql**（表设计与迁移） | 项目里有你负责的数据库表：要写 DDL、迁移脚本 | 无数据库；或数据库由别的团队/服务管，你只读不改结构；纯前端项目 |

**判不准就先关。** 后来需要了改配置一行就开，比开着不用、每次被追问「契约动了吗」强。

---

## 形态一 · 后端服务（前后端分离，自己管库）

两个可选类型**都开**。这是 docflow 最完整的形态。

```markdown
| 启用产物类型 | requirement, changes, notes, analysis, conventions, contract, sql |
| 目录名映射 | 无 |
| 变更记录层次映射 | 接口路径·字段 ↔ Controller 方法 ↔ Service 方法 ↔ 数据库表·字段 |
| 现状调查数据源 | <数据库连接/MCP，注明只读性与查询约束> |
| 接口契约载体 | <Swagger UI / Apifox / OpenAPI 文件路径> |
| 对端仓库 | ../<前端仓库>/（只读参考） |
```

链路：`requirement → contract（给前端）→ sql（建表）→ changes（三层对照）`。

---

## 形态二 · 前端应用（消费别人的接口）

**contract 关、sql 关。** 前端通常是接口的**消费方**——接口方案是后端给你的，不是你产出的。

```markdown
| 启用产物类型 | requirement, changes, notes, analysis, conventions |
| 目录名映射 | 无 |
| 变更记录层次映射 | 页面·路由 ↔ 组件 ↔ 状态/store ↔ 调用的接口 |
| 现状调查数据源 | 无，现状以代码为准 |
| 接口契约载体 | <后端的 Swagger/Apifox 地址（只读查阅，不是你维护的）> |
| 对端仓库 | ../<后端仓库>/（只读参考，用于核对接口口径） |
```

**例外——什么时候前端也该开 contract**：你在做组件库、微前端子应用、或对外的嵌入式 SDK，**别人要照着你的 props / 事件 / 初始化参数写代码**。这时 contract 产出的是「组件 API 变更说明」而不是「HTTP 接口方案」，八章骨架照用（把「接口清单」理解成「组件/API 清单」）。

**什么时候前端该开 sql**：几乎不会。除非项目里有 IndexedDB / SQLite 本地库且结构由你设计。

---

## 形态三 · 内部服务 / 库 / CLI（没有外部调用方）

**contract 关**；sql 看有没有库。

```markdown
| 启用产物类型 | requirement, changes, notes, analysis, conventions |
| 变更记录层次映射 | 公开 API ↔ 内部模块·类/函数 ↔ 数据源 |
| 现状调查数据源 | 无，现状以代码为准 |
| 接口契约载体 | 无 |
| 对端仓库 | 无 |
```

**注意**：如果这个库/CLI 是发布给别人用的（npm / PyPI / 内部 maven 仓），**它其实有外部调用方**——公开 API 的破坏性变更同样需要迁移说明，建议开 contract，第 ⑤ 章「破坏性变更与迁移」正是为此。

---

## 事后改主意怎么办

**改配置文件那一行即可**，不需要重新跑 setup：

```markdown
| 启用产物类型 | requirement, changes, notes, analysis, conventions, sql |   ← 加上 sql
```

- **从关到开**：下次用到时自然建目录（缺席不占位，不用预先 `mkdir`）。历史批次不用补——那些批次本来就没有这类产物。
- **从开到关**：已产出的目录**留着不动**（是历史记录），只是以后不再新增、相关必答问不再问。

## 目录名映射什么时候用

存量项目已经用别的名字叫这类产物时用，**别为了合规去改名**（改名会让历史会话、git 记录、文档间互引全部对不上）：

```markdown
| 目录名映射 | contract → frontend |
```

含义：配置里叫 `contract` 的产物类型，实际落在 `<落盘根>/frontend/` 下。skill 会按映射后的真实目录名读写。
