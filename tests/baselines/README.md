# RED 基线记录说明（2026-08-23）

本目录记录各 skill 的 RED 阶段基线：**没有该 skill 时，agent 面对压力场景的自然行为**。基线决定 skill 该教什么——没观察到的失败不写防御条款（writing-skills 铁律）。

## 本轮基线的两组对照

| 组 | 环境 | 意义 |
|---|---|---|
| **参照组**（10/10 完成） | 主会话派发的子代理，**继承了宿主项目的 CLAUDE.md 全文**（含四层目录规则、批次判据表、变更记录七项要求） | 相当于「规则以文档形式在场」的上限对照。**在此条件下仍然失守的条目 = 最需要 skill 强化的**；被规则挡住的条目 = 证明「把规则写清楚就管用」，正是 skill 对无 CLAUDE.md 项目的价值 |
| **干净组**（1/10 完成） | `/tmp` 独立沙箱 + headless CLI，**无任何项目规则注入** | 真·裸 agent。第 2 个起因账号额度耗尽中断（`You've hit your monthly spend limit`），未重跑 |

**为什么不补跑干净组**：额度耗尽是硬约束；且参照组已在「规则在场」的更严条件下暴露了核心失守点，证据方向一致（唯一跑成的干净组 req-s1 与参照组 req-s1 结论完全吻合，只是更糟）。已有证据足以定 RED，补跑只会重复验证。**这是有意的取舍，记录在此备查。**

## 测试设计缺陷与修正（值得记住）

参照组的 setup S1/S2 沙箱当时建在 docflow 仓库内部（`tests/tmp/`），子代理直接读到了仓库里当时尚未执行的实现计划文档——把「未来要实现的规范」当依据照做了，基线完全失真（它们甚至复现出 11 个配置字段名）。**沙箱必须放在被测仓库之外**（干净组已改到 `/tmp/docflow-red/`）。
