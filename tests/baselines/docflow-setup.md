## 仍然可用的观察

- **S1（全新项目）**：发现 `docflow-setup` 技能尚不存在，明确说「不因此搁置，也不自创一套做法」，转而照包内已定死的规范手动执行，并在生成的配置里注明此事。

## 结论 → skill 必须教什么

由于基线失真，本 skill 的内容**主要依据设计定案（spec §4）而非观测失败**，不写任何「对抗话术」类条款——没有观察到的失败不防御。可确认要写的：

1. 先检测再问（git？技术栈？有无存量落盘）。
2. 11 个配置字段的问答式生成，判不出的标「待确认」不编造（两组都自发这么做，说明是自然且正确的行为，写进 skill 是固化而非纠偏）。
3. 迁移模式：存量零改动 + 只生成配置 + 体检只转告不代修。
4. 骨架落地的具体命令（`.local` git init、exclude 写入不带尾斜杠、缺席原则不建空目录）。
